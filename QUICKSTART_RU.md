# Patrol RBM v4 — запуск на вашем роботе

Всё ниже рассчитано на установленный RBM с уже работающими SLAM, Nav2, `goal_proxy`, MediaMTX и Foxglove/Lichtblick. **Ничего из базового пайплайна не перезапускайте.**

## До начала

1. Остановите **старый** `./start_classroom.sh` в его терминале (`Ctrl+C`).
2. Убедитесь, что робот не движется; при первых испытаниях физический стоп должен быть под рукой.
3. Скопируйте каталог `rbm_patrol_v4` в репозиторий на Raspberry Pi: `~/robomarvel/PATROL-ROBOT/rbm_patrol_v4`.
4. На Raspberry Pi (хост) в терминале выполните `docker exec -it ros bash`.

## Команды внутри существующего Docker

```bash
cd /src/PATROL-ROBOT/rbm_patrol_v4
chmod +x *.sh
./preflight.sh
```

Нужны `0 errors`, работающий Nav2 action `/navigate_to_pose`, файлы NCNN и доступный ROS 2. Если предупреждение о звуке — патруль может работать без сирены в динамике.

```bash
./start.sh
```

**После запуска YOLO НЕ должна выполняться.** На старте только ROS-нода `/patrol_classroom_v4` публикует `IDLE`. Камера/YOLO включаются только после `START`.

В отдельном терминале, уже внутри Docker:

```bash
cd /src/PATROL-ROBOT/rbm_patrol_v4
./patrolctl.sh status
```

Ожидается `data: IDLE`.

## Работа в Lichtblick

1. Подключитесь к существующему мосту: `ws://IP_РОБОТА:8765`.
2. Импортируйте `rbm_patrol_v4/lichtblick/PATROL_RBM_v4.json`.
3. Проедьтесь по кабинету, чтобы SLAM нарисовал карту; её сохранение не нужно.
4. Выберите Click Point (frame `map`, topic `/clicked_point`) и нажмите на карту 2–10 раз на свободных участках.
5. Выберите LOOP и нажмите START. До двух проверенных кадров без человека робот **не начнёт движение**.
6. После обнаружения человека движение должно отмениться через Nav2. Только после подтверждённого завершения цели начинается QR-проверка.
7. `tools/PERSON_001.png` — разрешённый код; `tools/PERSON_999.png` — запрещённый. Без QR через 15 с — `DENIED`, сирена, блокировка до RESET.

Если Lighthouse/Lichtblick кнопки не работают, команды в терминале:

```bash
./patrolctl.sh loop
./patrolctl.sh start
./patrolctl.sh status
./patrolctl.sh stop
./patrolctl.sh reset
```

**STOP — это программная отмена Nav2, не физический аварийный выключатель.** Убедитесь глазами, что колёса реально остановились.

## Если Raspberry Pi снова перегружается

Не запускайте старые `leg_detector.py` или `route_manager.py` вместе с v4. Для ещё меньшей нагрузки перед стартом:

```bash
export PATROL_YOLO_FPS=1
export PATROL_IMGSZ=256
./start.sh
```

Точность обнаружения на 256 может снизиться. Даже на 1 FPS декодирование исходного 1280×720@30 RTSP-потока продолжается, пока камера включена. Если вся Raspberry Pi гаснет красным и теряет SSH, проверяйте питание и журналы ОС отдельно — частота YOLO не доказывает причину выключения.

## Что v4 не делает

- Не устанавливает ROS/Docker, не клонирует 93-МБ `robomarv_26`.
- Не сохраняет карту и не использует wheel encoder/IMU/Vosk.
- Не запускает follower и не преследует человека.
- Не вызывает `/goal/cancel`: патруль управляет **существующим Nav2 через action** `/navigate_to_pose`, чтобы ждать результат отмены.
- Не меняет RTSP/ WebRTC, параметры камеры в RBM, компоненты SLAM/Nav2.
